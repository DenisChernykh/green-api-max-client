# Выполнение тестового задания через MAX

Проверено по официальной документации GREEN-API 22 октября 2026 года. Это рабочие заметки к [исходному ТЗ](TASK.md), а не дополнительные требования работодателя.

## Вывод

Задание можно выполнить через MAX. Более того, в версии v5 MAX указан основным вариантом; WhatsApp и Telegram разрешены как запасные. Объём: простой React-интерфейс для отправки и получения текстовых сообщений, похожий на web.max.ru. В ТЗ отведено 5 дней; конкретная календарная дата сдачи в PDF не указана.

## Что подготовить

1. Аккаунт MAX с доступом к приложению на телефоне.
2. Учётную запись в [личном кабинете GREEN-API](https://console.green-api.com/).
3. Инстанс для MAX. Бесплатный **MAX Developer** позволяет работать с 3 чатами; в кабинете доступен 1 такой бесплатный инстанс. Для проверки сценария из ТЗ этого достаточно. `CheckAccount` ограничен 100 запросами в месяц. [Тариф и ограничения](https://green-api.com/v3/docs/about-tariffs/).
4. Авторизовать инстанс по QR-коду: в MAX открыть «Профиль → Устройства → Войти по QR-коду» и отсканировать код из кабинета GREEN-API. Целевой статус — `authorized`. Общая страница «Перед началом работы» всё ещё содержит оговорку об отключении пароля, но профильная документация [QR](https://green-api.com/v3/docs/api/account/QR/) и [SendAuthorizationPassword](https://green-api.com/v3/docs/api/account/SendAuthorizationPassword/) описывает авторизацию с паролем: после QR инстанс переходит в `pendingPassword`, затем пароль подтверждается отдельным методом. Отключать пароль по умолчанию не требуется; конкретные действия зависят от доступного интерфейса кабинета. Пароль MAX не передаётся в чат и не сохраняется в проекте. [Подключение](https://green-api.com/v3/docs/before-start/).
5. Получить `apiUrl`, `idInstance`, `apiTokenInstance` в параметрах инстанса. ТЗ явно требует ввод последних двух значений пользователем; адрес API также нужно учитывать в реализации. [Параметры доступа](https://green-api.com/v3/docs/before-start/#4).
6. Для полноценной проверки подготовить второго собеседника с аккаунтом MAX: он получит сообщение и ответит из мессенджера. Для сценария поиска по номеру документация `CheckAccount` поддерживает номера РФ и РБ с кодами `7` и `375`. [Поиск получателя](https://green-api.com/v3/docs/api/service/CheckAccount/).

## Настройка входящих сообщений

Для HTTP API у инстанса должен быть пустой `webhookUrl`, а получение входящих сообщений должно быть включено (`incomingWebhook: "yes"`). Это можно настроить в кабинете или через `SetSettings`. Публичный webhook endpoint для такого способа получения не требуется. [Документация HTTP API](https://green-api.com/v3/docs/api/receiving/technology-http-api/).

## Минимальная реализация

Предлагаемая схема приложения:

1. Экран подключения: поля `idInstance`, `apiTokenInstance` и способ указать `apiUrl`; проверка состояния инстанса.
2. Создание чата: нормализация телефона и вызов `CheckAccount`, сохранение полученного `chatId`.
3. Отправка текста через `SendMessage` с `chatId` и `message`. [Метод отправки](https://green-api.com/v3/docs/api/sending/SendMessage/).
4. Один последовательный цикл получения `ReceiveNotification`, обработка текстового сообщения, затем `DeleteNotification` по `receiptId`. [Получение](https://green-api.com/v3/docs/api/receiving/technology-http-api/ReceiveNotification/), [подтверждение обработки](https://green-api.com/v3/docs/api/receiving/technology-http-api/DeleteNotification/).
5. Сообщения в нужном чате, состояния загрузки и ошибки, остановка получения при выходе.

Для одного получателя следует последовательно использовать один и тот же `chatId`: отправка то по номеру с суффиксом `@c.us`, то по числовому `chatId` расходует две единицы квоты бесплатного тарифа. [Правила учёта чатов](https://green-api.com/v3/docs/about-tariffs/).

React обязателен по ТЗ. TypeScript и Vite можно выбрать для реализации, но они не являются требованиями работодателя. Необходимость промежуточного сервера и доступность API из браузера нужно проверить при первом подключении реального инстанса; запросы с реальными ключами пока не выполнялись.

## Проверка и сдача

- Проверить полный обмен: приложение → MAX собеседника → ответ из MAX → приложение.
- Подготовить GitHub-репозиторий и инструкцию локального запуска.
- Желательно опубликовать демо; скриншоты или видео приложить при наличии.
- Приложить резюме PDF с Telegram и указать предпочтительный формат работы.
- Адрес и тема письма сохранены в [ТЗ](TASK.md).

Реальный обмен с MAX и CORS ещё не проверены: инстанс не подключён, реальные сообщения не отправлялись. Запуск описан в [README](../README.md).
